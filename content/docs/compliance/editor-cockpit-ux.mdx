## North star

**One guided question:** _Is it safe to ship this process change?_

Open **Check change** in the editor toolbar to show the Modeling Cockpit.

### Three visible inputs

| Input                | Source                         | User control                                    |
| -------------------- | ------------------------------ | ----------------------------------------------- |
| **Proposal**         | Current editor buffer          | What you edited                                 |
| **Baseline**         | Saved file or `main` branch    | Baseline picker in cockpit header               |
| **Operational data** | Linked process cases + history | Inline summary chip; full detail in detail tabs |

### Guided flow

```text
Header (ready/blocked + controls) → Impact summary → Detail tabs → Ship verdict
```

Default landing: **Impact**. **Ship** is the terminal step.

## Tab map

| Tab           | Question                             |
| ------------- | ------------------------------------ |
| **Impact**    | What breaks if I ship?               |
| **Cases**     | Which open cases are guard-blocked?  |
| **History**   | Do historical paths still work?      |
| **Tests**     | Do regression tests pass?            |
| **Ingestion** | Do connected sources cover evidence? |
| **Structure** | Is the graph and schema valid?       |
| **Ship**      | Safe to save?                        |

## What is live?

Process models in the editor follow three layers — there is **no separate “activate” button** beyond linking a process and saving the file.

| Layer                 | What it is                                                            | Affects live cases?                                                                        |
| --------------------- | --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| **Editor buffer**     | What you see while typing                                             | **No** — preview only (Modeling Cockpit **Check change** uses this as the proposal)        |
| **Saved file**        | Written to the workspace repo clone (manual **Save** or ~2s autosave) | **Yes**, when a [process twin](#process-twin) is linked to this path                       |
| **Git commit / push** | Version history and CI on `main`                                      | **No extra runtime step** — commit is for audit and team workflow, not a second activation |

### Process twin

A **process twin** is a platform `process` record whose `currentConfigPath` points at this workflow file (for example `.kiket/workflows/vendor-onboarding.yaml`). The API reads that path from the linked repo when:

- Resolving case transitions and guards
- Running the compliance scanner against operational cases
- Building simulation **Cases** / **History** tabs in the Modeling Cockpit

If no twin is linked, you can still edit and save YAML in git — but open cases will not use the model until onboarding or workspace setup creates a monitored process for this path.

The editor shows a **config lifecycle** strip above the canvas: pending save (amber), live config (green), or saved but unlinked (neutral).

## Workflow editor chrome (shipped 2026-05)

The workflow canvas uses a **mode bar** and **right inspector** instead of a bottom Process drawer:

| Surface             | Purpose                                                                                                     |
| ------------------- | ----------------------------------------------------------------------------------------------------------- |
| **Mode bar**        | Segmented **Graph \| YAML \| Diff**; undo/redo; Layout/Fit on graph only                                    |
| **Right inspector** | **Selection** (node/edge fields) \| **Evidence & checks** (evidence, checks, remediation, regression tests) |
| **Page header**     | Save, **Check change**, Git (workspace actions)                                                             |

Coverage warnings on the canvas banner link to **Evidence & checks**. Cockpit **Edit** actions on Tests and Ingestion open the same inspector tab.

## Deep links

Share or bookmark a specific cockpit view with URL query params on the editor:

| Param      | Value       | Meaning                                  |
| ---------- | ----------- | ---------------------------------------- |
| `simulate` | `1`         | Open the Modeling Cockpit bottom panel   |
| `tab`      | see tab map | Active detail tab (`impact`, `cases`, …) |

Example: `/editor?file=.kiket/workflows/vendor-onboarding.yaml&simulate=1&tab=cases`

Tab changes update the URL in place so refresh and share round-trip.

## Shipped UX

- **Compact cockpit header** — ready/blocked chip, operational summary, baseline picker, re-run, auto-check, and tabs on one row; blocker chips only when present
- **Impact default** — aggregated status rows drill into detail tabs
- **Capture test** — from Cases rows; toast + highlight; duplicate detection
- **Add test** / **Edit** — opens Evidence & checks → regression tests
- **Ingestion** — source health, coverage gaps, **Edit evidence requirements** → Evidence & checks
- **Re-run check**, auto-check toggle, baseline picker (saved vs `main`)
- **Ship** tab — Fix links to detail tabs; Save when ready
- **Live lens legend** on canvas overlay
- **URL state** — `?simulate=1&tab=<tab>` deep links; inline package process cockpit retired

## Walkthrough (30 seconds)

<Steps>

<Step>

### Open the cockpit

Open a workflow in the editor and click **Check change**.

</Step>

<Step>

### Read readiness

Scan the **cockpit header**: ready/blocked chip, operational summary (hover for proposal/baseline detail), baseline picker, and re-run controls.

</Step>

<Step>

### Scan impact

Start on **Impact** — scan status rows; click a row to jump to the failing detail tab.

</Step>

<Step>

### Review cases

On **Cases**, see guard-blocked open cases; use **Capture test** to seed a regression test from a failing row.

</Step>

<Step>

### Confirm tests

On **Tests**, confirm YAML scenarios pass; **Edit** opens structured scenario fields in Evidence & checks.

</Step>

<Step>

### Ship when ready

On **Ship**, review blocking checks; use **Fix** to jump back, then **Save** when ready.

</Step>

</Steps>

## Acceptance criteria

Within 30 seconds of opening the cockpit, a user can answer:

1. What is being checked?
2. Against what baseline and how many live cases?
3. What failed?
4. What is the next action?
