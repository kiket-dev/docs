Shipped first-party adapter: `@kiket/jira-adapter` (`kiket-ext-jira`).

## What it ingests

| Jira webhook            | Normalized event   | Evidence        |
| ----------------------- | ------------------ | --------------- |
| `jira:issue_created`    | `case.updated`     | `jira_issue`    |
| `jira:issue_updated`    | `case.updated`     | `jira_issue`    |
| `comment_created`       | `evidence.observed`| `jira_comment`  |

Link operational cases by embedding `case: <uuid>` in the Jira issue description or comment body.

## Webhook endpoint

```
POST /api/v1/integrations/jira/webhook
```

Required headers:

- `X-Kiket-Organization-Id`
- `X-Kiket-Event-Source-Key`

Optional shared secret: store `webhookSecret` on the event source configuration (sealed at rest). Invalid signatures are quarantined.

## Process template

Use the `jira-change` definition pack (`.kiket/workflows/jira-change.yaml`) for divergence checks on owner assignment and status alignment.

## Findings this unlocks

- Case status diverges from Jira issue status evidence
- Missing owner on in-progress work
- Required Jira issue evidence missing before case completion
