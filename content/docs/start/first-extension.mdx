Kiket ships **evidence adapters** as installable extensions — `kiket-extension.yaml` at the repo root, normalization via the SDK, and ingress through `/platform/*` with scoped API keys.

## Install Slack (catalog-hosted)

<Steps>

<Step>

### Open evidence sources

In the web app go to **Settings → Evidence sources** (or use [Install in app](https://kiket.dev/marketplace) from the public marketplace with `?install=kiket-ext-slack`).

</Step>

<Step>

### Install from the extension catalog

Under **Extension catalog**, choose **Slack evidence adapter** and click **Install with Kiket runner** (or configure push/pull transport). Copy the runner API key when shown — it is displayed once.

</Step>

<Step>

### Register an event source

Register a Slack webhook source with `POST /platform/event-sources` (or the in-app wizard). Point Slack at `POST /integrations/slack/webhook` with `X-Kiket-Organization-Id` and `X-Kiket-Event-Source-Key`.

</Step>

<Step>

### Verify ingestion

Post a test payload with `kiket extension test` or send a real message; confirm raw events normalize and appear on linked cases.

</Step>

</Steps>

## What adapters do

- **Ingress only** — adapters call Kiket (or receive webhooks on Kiket ingress routes), not outbound issue webhooks from core.
- **Scoped keys** — runner keys use `raw-events:submit` and `raw-events:claim`; org API keys use least-privilege scopes.
- **Explainable evidence** — normalized types feed the scanner; findings link back to proof.

## Build or publish your own

1. `kiket extension init` — scaffold manifest + adapter.
2. `kiket extension validate` / `kiket extension test` — local checks.
3. `kiket extension publish` — list in your org catalog (optional `gitUrl` for pull installs).

See **[Extension adapters](/docs/compliance/extension-adapters)** and **[Evidence adapters (API)](/docs/api/extensions)**.
